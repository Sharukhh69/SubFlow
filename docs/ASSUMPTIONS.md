# SubFlow — Assumptions

## Business Assumptions

1. **Currency**: INR (₹) only — no multi-currency support in v1.
2. **Single-tenant**: One company (Brightloop Software) runs the platform.
3. **GST**: GST is the primary tax system; invoices show the customer's GSTIN if provided.
4. **Overpayment**: Not allowed by default. The `amount` must be ≤ outstanding balance unless explicitly flagged.

## Technical Assumptions

5. **`AUTO_CONFIRM_INVOICES=true`**: When set, invoices generated by the billing job are auto-confirmed (and optionally auto-emailed).
6. **Discount stacking policy**: The **best single discount** applies per invoice — no stacking of multiple discounts.
7. **Billing job schedule**: Runs daily at 00:30 UTC via `@nestjs/schedule` cron. Also triggerable via `POST /api/billing/run` (admin only) with an optional `dryRun` flag.
8. **Customer self-signup**: Creates both a `User` (role=CUSTOMER) and a linked `CustomerProfile` in one transaction.
9. **Refresh tokens**: Stored as SHA-256 hashes. Family-based rotation — reuse of a refresh token from a revoked family invalidates the entire family (security: token theft detection).
10. **Month-end date arithmetic**: Jan 31 + 1 month = Feb 28 (or 29 on leap year), not Mar 3. Uses `date-fns` `addMonths`.
11. **OVERDUE is derived**: Not stored in DB. Computed as: `status = CONFIRMED AND dueDate < today AND (grandTotal - amountPaid) > 0`.
12. **Subscription numbers**: Format `SUB-000001`. Managed by `SequenceCounter` table with `SELECT ... FOR UPDATE` locking to prevent gaps or duplicates.
13. **Invoice numbers**: Format `INV-YYYY-000001` (year-scoped). Managed by `SequenceCounter` with locking.
14. **Staff management**: Staff can be deactivated (soft-delete via `isActive=false`) but never hard-deleted. Preserves audit history.
15. **Product archiving**: Products are soft-deleted (`isActive=false`), never hard-deleted if referenced in any subscription or invoice.
16. **Reminder email rate-limiting**: Maximum one reminder email per invoice every 3 days, tracked via `Invoice.reminderSentAt`.
17. **Neon Postgres connection**: Pooled connection string (`?pgbouncer=true`) for app runtime; direct connection string for Prisma migrations (`directUrl`).
18. **`FOR UPDATE SKIP LOCKED`**: Implemented via `prisma.$queryRaw` for concurrency-safe billing job. Ensures no two job instances process the same subscription.
19. **Seed determinism**: All randomness uses a seeded PRNG (seedrandom) so `npm run seed` produces identical data every time.
20. **Force password change**: A `forcePasswordChange` flag on `User` — when `true`, the API returns a 403 with `{ requiresPasswordChange: true }` until the user sets a new password.
21. **Dashboard caching**: In-memory cache (cache-manager) for 60 seconds on dashboard summary queries. Invalidated after billing runs and payment recordings.
22. **Quotation expiry job**: Daily cron marks QUOTATION-status subscriptions as CLOSED if their `quoteExpiryDate` has passed.
23. **Plan availability window**: A plan can only be used for new subscriptions if today is within `availableFrom` → `availableTo` (inclusive). If both are null, the plan is always available.
24. **Subscription lines are immutable after CONFIRMED**: Once a subscription moves past DRAFT, its lines cannot be edited. A new subscription or renewal must be created.
25. **Invoice snapshots**: Invoice lines store `productName` and `variantLabel` as strings at billing time. Future price changes never alter historical invoices.

## Deployment Assumptions

26. **Backend on Render free tier**: Cold starts are expected. The `/api/health` endpoint is intentionally lightweight (single `SELECT 1`). The README mentions the uptime-ping tip.
27. **Frontend on Vercel**: SPA rewrites configured in `vercel.json`. All routes resolve to `index.html`.
28. **CORS + cookies in production**: `SameSite=None; Secure` on the refresh token cookie; `trust proxy` enabled on the Express app for Render's proxy layer.
